# expert → producer: Решение неясностей в спецификации

Прочитал спецификацию и твои 5 уточнений. Вот мои решения по каждому пункту:

## 1. Правило удаления завершающих нулей

**Решение**: УДАЛЯЮТСЯ ВСЕ завершающие нули после десятичной точки.

Текущее правило на строке 46 противоречиво. Правильно:
- 32 (не 32.00)
- 98.6 (не 98.60)
- 273.15 (остаётся как есть, нет завершающих нулей)

**Что делать в спецификации**: Удалить фразу "except trailing zeros after the first decimal place are kept for consistency" и переписать строку 46:
- "Trailing zeros after the decimal point are removed" (всё просто).
- Или более чётко: "The result is printed with minimal necessary decimal places (up to 2). All trailing zeros are removed after the decimal point."

## 2. Регистр букв шкалы

**Решение**: ОБЯЗАТЕЛЬНО капсом (C, F, K). Нижний регистр — ошибка.

Строка 107 уже говорит правильно: "Scale letters are case-sensitive."
Строка 138 должна быть переписана: удалить "(if case-sensitivity enforced)" и сделать это обязательным:
- Изменить: `tempconv 0 c f` → error (exit 1) — lowercase scales **are not allowed**

## 3. Алгоритм округления

**Решение**: Round-half-up не обязателен. Любой стандартный метод округления (round-half-up, round-half-to-even, banker's rounding) приемлем, если результаты совпадают с примерами в спецификации.

**Зачем**: Разные языки программирования используют разные способы по умолчанию. Главное — результаты должны быть точны до 2 знаков и совпадать с приведёнными примерами.

Строка 104 уже хороша, но уточню в спецификации:
- "Implementations may use any standard floating-point rounding method (round-half-up, round-half-to-even, etc.). Results must match the provided examples within the 2 decimal place precision."

## 4. Сообщение об ошибке для пропущенного аргумента

**Решение**: Точное сообщение не требуется. Достаточно exit 1.

Это исключение из общего правила, потому что:
- Обработка пропущенных аргументов обычно происходит в парсере CLI, а не в нашем коде
- Разные фреймворки (argparse, getopt, Click и т.д.) выводят разные сообщения
- Главное, что требуется — выход с кодом 1

**В спецификации** оставить как есть (строка 100) или переписать яснее:
- "(Missing required argument - exit code 1 required; exact message is implementation-specific)"

## 5. Диапазон "типичных" температур

**Решение**: "Типичные" = обычные земные условия (-50 до +50°C). Но гарантия точности 2 знаков распространяется на ВСЕ физически возможные значения (включая экстремальные вроде -273.15°C).

**Уточнение**:
- Реализации должны поддерживать точность до 2 знаков для диапазона от 0K (абсолютный ноль) до любых экстремальных значений, которые могут передать.
- Для очень больших чисел (например, 1000000 K) результаты должны быть округлены до 2 знаков после запятой (что в этом случае означает округление до целого числа из-за масштаба).

**В спецификации**: Переписать строку 105:
- "Implementations should aim for accuracy to at least 2 decimal places for all temperature values in the valid range (from absolute zero, 0K and above). For very large numbers, rounding applies at the 2 decimal place precision as specified in the Output Format section."

## Итого

Пять пунктов проясняются следующим образом:
1. Удалять ВСЕ завершающие нули ✓
2. Капс (C, F, K) — обязателен ✓
3. Любой стандартный метод округления ✓
4. Пропущенные аргументы: exit 1, сообщение зависит от реализации ✓
5. Точность для всего диапазона, не только "типичных" температур ✓

Прошу обновить спецификацию и убедиться, что все 5 пунктов теперь однозначны. После этого — спецификация готова к передаче другой команде.
