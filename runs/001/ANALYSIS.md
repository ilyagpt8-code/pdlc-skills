# Разбор прогона 001 (ансамбль spec; app не запускался)

Кругов 1, расход ≈ $0.32 (оценка расписания), почта 2 сообщения.

## Находки
1. **Скиллы продюсера и хореографа не загружены.** Оба вызвали `Skill(...)` → `Unknown skill` (`spec-producer.jsonl`, `spec-choreographer.jsonl`), файлы `SKILL.md` не открывали и работали по своему пониманию роли. Причина: список скиллов облачной сессии строится при её старте, а скиллы переехали в `.claude/skills/` позже. Прогон 001 скиллы **не проверял**.
2. **Продюсер принял работу самооценкой.** В журнале — список «проверены: синтаксис, формулы, коды…» и `ГОТОВО`; метрики нет, независимого счёта нет, строк `метрика:` нет. Ровно то, от чего скилл предостерегает (раздел 1).
3. **Результат не там, где сказано в задании:** `runs/001/spec/tempconv.md` вместо `spec/tempconv.md`. Не заметили ни продюсер, ни хореограф. Из-за этого app не стартовал.
4. **Шаг приёмки выпал.** По заданию спецификацию принимает эксперт. В карточке ролей хореографа принимающим стал продюсер; эксперт после первого сообщения в работе не участвовал. Хореограф записал «трения нет» по всем признакам.
5. Мелочь: эксперт упомянул «поведение при интернет-отключении» для офлайн-утилиты — шум.

## Что изменено ко второму прогону
- Расписание: стартовое поручение ссылается на файл скилла (`прочитай .claude/skills/<роль>/SKILL.md`), а не на `Skill(...)`; если скилл не прочитан — остановить прогон.
- Скилл продюсера: «если проверяющего нет — счётчик запускаешь сам, но считаешь остаток (вопросы без ответа по своим тестам)»; условия «ГОТОВО» (метрика с источником на цели, путь и формат дословно по заданию, приёмка тем, кого называет задание).
- Скилл хореографа: карточка ролей из задания дословно; сначала сверка «задание ↔ что произошло»; «трения нет» нужно доказать.
