# Сообщение продюсера к эксперту (Ход 1)

## Проблема: нет метрики, команда идит вслепую

Инструмент прогресса сообщает: метрики нет. Это критично. Без числовой метрики я не вижу, приближается ли команда к результату, и не могу определить, когда работа готова.

## Предложение метрики

Твоя роль — знать спецификацию и судить, соответствует ли ей программа. Предлагаю использовать это для метрики:

**Метрика: Число требований спецификации, которые программа НЕ выполняет.**

Источник — ты: ты проверяешь код против spec/tempconv.md, и считаешь, сколько требований из спецификации нарушено.

## Как измерять

Каждый раз, когда исполнитель сообщит о завершении версии, проверь программу против списка требований спецификации. Вот что проверить:

1. **Аргументы**: Поддерживает VALUE, FROM, TO (3 аргумента)
2. **Типы VALUE**: Int, decimal, scientific notation (`1e2`, `1e-5`)
3. **Шкалы**: Только C, F, K (uppercase, rejection на lowercase)
4. **Валидация VALUE**: Отклоняет нечисло (exit 1, "Error: invalid number")
5. **Валидация шкал**: Отклоняет неверные коды (exit 2, "Error: invalid scale")
6. **Абсолютный ноль C**: Отклоняет < -273.15 (exit 3)
7. **Абсолютный ноль F**: Отклоняет < -459.67 (exit 3)
8. **Абсолютный ноль K**: Отклоняет < 0 (exit 3)
9. **Same-scale**: C→C, F→F, K→K просто форматируют значение
10. **Конвертация C→F**: (C × 9/5) + 32 ✓
11. **Конвертация C→K**: C + 273.15 ✓
12. **Конвертация F→C**: (F − 32) × 5/9 ✓
13. **Конвертация F→K**: ((F − 32) × 5/9) + 273.15 ✓
14. **Конвертация K→C**: K − 273.15 ✓
15. **Конвертация K→F**: (K − 273.15) × 9/5 + 32 ✓
16. **Форматирование**: Ровно 2 знака после запятой
17. **Rounding**: Round-half-up (32.125 → 32.13, −32.125 → −32.13)
18. **Whitespace**: Leading/trailing пробелы игнорируются
19. **Exit codes**: 0 успех, 1 для числа/аргументов, 2 для шкал, 3 для абнуля
20. **Stderr**: Ошибки на stderr, успех на stdout

Проверяй примеры из спецификации:
- `tempconv 0 C F` → stdout: `32.00` (exit 0)
- `tempconv 32 F C` → stdout: `0.00` (exit 0)
- `tempconv 100 C K` → stdout: `373.15` (exit 0)
- `tempconv 25 C C` → stdout: `25.00` (exit 0)
- `tempconv -273.15 C F` → stdout: `−459.67` (exit 0)
- `tempconv 0 K C` → stdout: `−273.15` (exit 0)
- `tempconv -459.67 F K` → stdout: `0.00` (exit 0)

После проверки версии напиши в journal.md одну строку:
```
метрика: требований_не_выполнено=N [источник: проверки эксперта версия V]
```

где N — число требований из списка выше, которые программа нарушает (0 = всё верно, 20 = ничего не работает).

## Что будет успехом

Следующий отрезок будет успешным, если метрика: требований_не_выполнено=0
