# Уточнения для версии 2 спецификации

Привет! Прочитал обсуждение между тобой и producer. Producer одобрил план на версию 2 с 4 критичными уточнениями. Вот мои рекомендации по каждому пункту:

## 1. Метод округления

**Рекомендация**: Используй **round-half-up** (стандартное школьное округление).

Почему: это самый предсказуемый и понятный метод. Например:
- 32.125°F → 32.13 (round up)
- 32.124°F → 32.12 (round down)
- 32.115°F → 32.12 (round up)

**Текст для спеца**: "Output precision: 2 decimal places using round-half-up method (standard rounding: 0.5 and above rounds away from zero)."

## 2. Абсолютный нуль — строгость проверки

**Рекомендация**: Проверяй **строго**: если значение < минимума, это ошибка. Но **игнорируй floating-point погрешности на уровне ±1e-9**.

Почему: иначе значение ровно -273.15 будет отвергнуто из-за ошибки представления чисел.

**Текст для спеца**: "Absolute zero validation: input temperature must not be below the minimum for its scale. Validation uses strict comparison (≥ for Kelvin, ≥ limit for C/F). Floating-point representation errors within ±1e-9 of the boundary are acceptable."

Примеры:
- `-273.15` C → OK (ровно граница)
- `-273.1500000001` C → OK (в пределах допуска)
- `-273.16` C → Error (явно ниже)

## 3. Порядок проверки ошибок

**Рекомендация**: Вот точный порядок:
1. Проверка кол-ва аргументов (должно быть ровно 3)
2. Проверка формата VALUE (может ли быть спарсено как число)
3. Проверка scale кодов (FROM и TO должны быть в {C, F, K})
4. Проверка абсолютного нуля (VALUE не ниже для scale FROM)

**Текст для спеца**: "Error checking order: 1) argument count (3 required); 2) VALUE numeric format; 3) scale codes (C, F, K only); 4) absolute zero constraint on input. Report first error encountered."

Это гарантирует, что на одном и том же неверном вводе все реализации выведут одну и ту же ошибку.

## 4. Формат вывода для всех значений

**Рекомендация**: **Всегда ровно 2 знака после запятой**, без исключений.

Почему: это предсказуемо для скриптов и тестов. Даже большие числа вроде `1000000.00`.

**Текст для спеца**: "Output format: always exactly 2 decimal places, even for very large or very small numbers. Example: 1000000.00, 0.00, -0.00 is normalized to 0.00."

### Edge cases в формате вывода:
- Очень большие числа (1e20): выводить `100000000000000000000.00` (не научная нотация)
- Очень малые числа (1e-10): выводить `0.00` (из-за требования 2 decimal places)
- Отрицательный ноль: нормализовать на `0.00` (без минуса)
