# Установка движка в живой ансамбль (инструкция для центральной сессии)

Эту инструкцию выполняет **центральная сессия ансамбля** (например, архитектор) по
просьбе владельца. Движок лежит в `D:\Work\projects\AIDD\pdlc-group\pdlc-skills-repo`
(дальше — `<движок>`); что он такое — `<движок>\README.md`, разделы 1 и 6.

Главное правило: **движок подключается файлами и отдельными сессиями, ничего не
встраивается в работающие сессии и в настройки.** Всё, что ты создашь, перечисли в
отчёте владельцу — по этому списку движок и снимается.

## Что можно ставить

| Что | Как работает | Кто запускает |
|---|---|---|
| Продюсер-наблюдатель | раз в 2 ч снимок ансамбля → запись «что вижу, что сказал бы команде»; в сессии не пишет | владелец (новая локальная сессия) |
| Хореограф-наблюдатель | то же про стыки: кто кого ждёт, очередь у узла | владелец |
| Тестировщик | скилл роли: виды входа от цели → пропуски как метрика | ты кладёшь скилл; роль — новая сессия или существующая, по решению владельца |
| Вопросы владельцу и компас | скилл `owner-questions` и шаблон компаса | ты кладёшь скилл, компас собираешь с владельцем |

Участие продюсера и хореографа (письма в сессии ансамбля) **не ставится** — только наблюдатели.

## Шаги

1. **Состав ансамбля.** Определи сессии ансамбля и их роли (короткие имена латиницей:
   `architect`, `vm`, …) и префиксы id их журналов в `C:\Users\User\.claude\projects\*\<id>.jsonl`
   (по заголовкам сессий; если сомневаешься — спроси владельца). Запиши файл ролей
   **вне репозиториев**: `C:\Users\User\.pdlc\observers\<ансамбль>-roles.txt`, строки
   `роль=префикс_id`. Если файл уже есть — сверь и не дублируй.
2. **Проверка снимка:**
   ```
   python <движок>\tools\observe.py C:\Users\User\.pdlc\observers\<ансамбль>-roles.txt C:\Users\User\.pdlc\observers\<ансамбль>-snap
   ```
   Должно быть «снимок готов». Открой `mail_stats.md`: роли ансамбля в матрице есть,
   «other_…» — только сессии вне ансамбля. Не так — поправь файл ролей.
3. **Скиллы — только те, что владелец попросил.** Скопируй папку скилла из
   `<движок>\.claude\skills\<скилл>` в `.claude\skills\` своего проекта (`tester`,
   `owner-questions`). Продюсеру и хореографу-наблюдателям копировать скиллы не нужно:
   они работают из папки движка.
4. **Команды запуска наблюдателей — владельцу.** Новые сессии создаёт владелец.
   Сформируй для каждого наблюдателя готовую строку (подставь ансамбль):
   - сессия: **локальная** Claude Code, папка `<движок>`, модель Haiku;
   - задание продюсера:
     ```
     /loop 2h Ты — продюсер-наблюдатель ансамбля <ансамбль>. Выполни один проход по observers/live-producer.md; файл ролей — C:\Users\User\.pdlc\observers\<ансамбль>-roles.txt, папка снимка — C:\Users\User\.pdlc\observers\<ансамбль>-snap.
     ```
   - задание хореографа — то же с `observers/live-choreographer.md` и словом «хореограф-наблюдатель».
5. **Отчёт владельцу** одним сообщением: что поставлено (файлы и папки — полными путями),
   команды запуска наблюдателей, где будут записи
   (`C:\Users\User\.pdlc\observers\<ансамбль>-producer-notes.md`, `…-choreographer-notes.md`),
   и как снять (ниже).

## Как снять

- Наблюдатели: владелец останавливает или закрывает их сессии. Записи и снимки — в
  `C:\Users\User\.pdlc\observers\` (удалить при желании).
- Скиллы: удалить скопированные папки из `.claude\skills\` проекта.
- Больше движок ничего не оставляет.

## Чего не делать

- Не ставить наблюдателей в облачную сессию: журналов ансамбля там нет.
- Не класть файл ролей, снимки и записи в репозитории: там переписка с данными заказчиков.
- Не менять настройки, хуки и разрешения сессий.
