# Установка движка в живой ансамбль (инструкция для центральной сессии)

Эту инструкцию выполняет **центральная сессия ансамбля** (например, архитектор) по
просьбе владельца. Движок лежит в `D:\Work\projects\AIDD\pdlc-group\pdlc-skills-repo`
(дальше — `<движок>`); что он такое — `<движок>\README.md`, разделы 1 и 6.

Главное правило: **движок подключается файлами и отдельными сессиями, ничего не
встраивается в работающие сессии и в настройки.** Всё, что ты создашь, перечисли в
отчёте владельцу — по этому списку движок и снимается.

## Что можно ставить

| Что | Как работает | Кто запускает |
|---|---|---|
| **Скилл участника** (`ensemble-member`) | **всем сессиям ансамбля**: что отвечать продюсеру и хореографу, строка метрики-остатка, «закрывай петли» (решение владельца — тем, кто спрашивал), коротко | ты кладёшь скилл в рабочую папку каждой сессии и пишешь каждой одно письмо о подключении |
| Продюсер | раз в 2 ч снимок ансамбля → только важное: курс, бюджет, стена. Режим **наблюдатель** (пишет только в записи) или **участник** (пишет сессиям, не больше двух писем за проход) | владелец (новая локальная сессия) |
| Хореограф | то же про стыки: кто кого ждёт, очередь у узла, недошедшие решения | владелец |
| Тестировщик | скилл роли: виды входа от цели → пропуски как метрика | ты кладёшь скилл; роль — новая сессия или существующая, по решению владельца |
| Вопросы владельцу и компас | скилл `owner-questions` и шаблон компаса | ты кладёшь скилл, компас собираешь с владельцем |

Команда образуется, только если **все** её сессии знают про продюсера и хореографа и
отвечают им — поэтому скилл участника ставится всегда, когда ставятся продюсер или
хореограф. Режим (наблюдатель или участник) выбирает владелец; по умолчанию —
наблюдатель.

## Шаги

1. **Состав ансамбля.** Определи сессии ансамбля и дай им короткие роли латиницей
   (`architect`, `vm`, …). **Ты сам — тоже роль ансамбля** (обычно узел): найди свой
   журнал по своему заголовку и включи его. Имя ансамбля — короткое латиницей
   (по проекту, например `tpat`, `enkod`); оно идёт в имена файлов. Журналы сессий найдёт инструмент — по заголовкам:
   ```
   python <движок>\tools\find_sessions.py "<часть заголовка>" ["<ещё часть>" …] --days 30
   ```
   Он печатает 8-значный префикс id, заголовок, последнюю активность и папку проекта.
   Бери сессии **своего** ансамбля: те, что назвал владелец, и те, с кем ты сам
   переписываешься; папка проекта у них обычно одна. Сессии с похожими словами из
   другого проекта — не твои. Не уверен в составе — спроси владельца, перечислив
   найденное (префикс и заголовок).
   Запиши файл ролей **вне репозиториев**: `C:\Users\User\.pdlc\observers\<ансамбль>-roles.txt`,
   строки `роль=префикс` (8 знаков из вывода инструмента). Если файл уже есть и состав расходится — не перезаписывай, спроси владельца.
2. **Проверка снимка:**
   ```
   python <движок>\tools\observe.py C:\Users\User\.pdlc\observers\<ансамбль>-roles.txt C:\Users\User\.pdlc\observers\<ансамбль>-snap
   ```
   Инструмент напечатает для каждой роли взятый журнал **с заголовком сессии** —
   сверь, те ли это сессии. Затем открой `mail_stats.md`: роли ансамбля в матрице
   есть; `<роль>_sub` — субагенты этих ролей (это нормально); «other_…» — сессии вне
   ансамбля. Если «other_…» активно переписывается с ансамблем (десятки писем) —
   возможно, это его участник: перечисли такие в отчёте как вопрос владельцу, сам
   не добавляй. Ошибся с сессией роли — поправь файл ролей и повтори.
3. **Скиллы.** Рабочие папки сессий печатает `find_sessions.py` (в квадратных скобках).
   - **Всегда** (если ставятся продюсер или хореограф): скопируй `<движок>\.claude\skills\ensemble-member`
     и `<движок>\.claude\skills\owner-questions` в `.claude\skills\` **рабочей папки каждой
     сессии** ансамбля (если у нескольких сессий одна папка — один раз).
   - Тестировщика (`tester`) — только если владелец попросил.
   - Продюсеру и хореографу копировать их скиллы не нужно: они работают из папки движка.
   - **Каждой сессии ансамбля** (и себе) — одно письмо: «Владелец подключил к ансамблю
     продюсера и хореографа (режим: <наблюдатель/участник>). В твоей рабочей папке
     появился скилл `ensemble-member` — прочитай его: что им отвечать, как сообщать
     остаток и передавать решения владельца.» Сессия скилл увидит в следующем ходе.
4. **Команды запуска наблюдателей — владельцу.** Новые сессии создаёт владелец.
   Сформируй для каждого наблюдателя готовую строку (подставь ансамбль):
   - сессия: **локальная** Claude Code, папка — любая (пути в задании полные), модель **Sonnet 5.5** (не Haiku и
     не поколение 5): наблюдатель судит о работе сильной команды и о том, кто кого
     реально ждёт, — это работа аналитика; Haiku в движке — для исполнителей ролей в
     коротких прогонах, не для наблюдения за живым ансамблем;
   - режим разрешений сессии — такой, чтобы она могла без подтверждений запускать
     `python` в папке движка и писать в `C:\Users\User\.pdlc\observers\` (например,
     авто-режим); иначе проход по расписанию остановится на первом запросе разрешения,
     пока владелец не подтвердит;
   - на вопрос Claude Code, где держать цикл `/loop`, выбрать **«This session only»**: журналы
     ансамбля есть только на этом компьютере, в другом месте наблюдатель их не увидит;
   - у каждого наблюдателя **своя** папка снимка: снимок пересобирается каждый проход, и
     два наблюдателя в одной папке мешают друг другу;
   - режим — слово в задании: «наблюдатель» или «участник» (как сказал владелец);
   - задание продюсера:
     ```
     /loop 2h Ты — продюсер ансамбля <ансамбль>, режим <наблюдатель|участник>. Выполни один проход по D:\Work\projects\AIDD\pdlc-group\pdlc-skills-repo\observers\live-producer.md; файл ролей — C:\Users\User\.pdlc\observers\<ансамбль>-roles.txt, папка снимка — C:\Users\User\.pdlc\observers\<ансамбль>-snap-producer.
     ```
   - задание хореографа:
     ```
     /loop 2h Ты — хореограф ансамбля <ансамбль>, режим <наблюдатель|участник>. Выполни один проход по D:\Work\projects\AIDD\pdlc-group\pdlc-skills-repo\observers\live-choreographer.md; файл ролей — C:\Users\User\.pdlc\observers\<ансамбль>-roles.txt, папка снимка — C:\Users\User\.pdlc\observers\<ансамбль>-snap-choreographer.
     ```
5. **Отчёт владельцу** одним сообщением: состав (роль — префикс — заголовок),
   вопросы по составу (если есть), что поставлено (файлы и папки — полными путями),
   команды запуска наблюдателей, где будут записи
   (`C:\Users\User\.pdlc\observers\<ансамбль>-producer-notes.md`, `…-choreographer-notes.md`),
   и как снять (ниже).

## Как снять

- Наблюдатели: владелец останавливает или закрывает их сессии. Записи и снимки — в
  `C:\Users\User\.pdlc\observers\` (удалить при желании).
- Скиллы: удалить скопированные папки (`ensemble-member`, `owner-questions`, `tester`) из
  `.claude\skills\` рабочих папок сессий.
- Больше движок ничего не оставляет.

## Чего не делать

- Не класть файл ролей, снимки и записи в репозитории: там переписка с данными заказчиков.
- Не менять настройки, хуки и разрешения сессий.
