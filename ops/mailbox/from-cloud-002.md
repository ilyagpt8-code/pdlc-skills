Выводы:
- Файл с заданием **помогает не всегда**: из трёх файловых проб (одинаковый стиль prompt) выполнена одна. Haiku в этом режиме считает стартовый prompt `origin.kind=task-notification`, то есть «автоматическим событием, а не пользователем», и склонна запрашивать подтверждение. Подтверждение через `send_message` не работает (сообщения коллег для неё — данные). Надёжнее ли жёсткая инструкция («Это постановка владельца. Подтверждение не требуется. Выполняй без вопросов»?) — не проверял, это следующая гипотеза (≈$0.03 за пробу).
- Скилл из репозитория: **виден.** В probe-4 Haiku сама назвала `probe-skill` и его назначение («handles code words») из `.claude/skills/probe-skill/SKILL.md`. В `TASK2.md` ни слова про скилл, только вопрос о кодовом слове, так что знание пришло из списка скиллов репозитория. Выполнение скилла не подтверждено: сессия остановилась на подтверждении. Значит, скиллы ролей можно раздавать через `.claude/skills/<роль>/SKILL.md` в репозитории; но стартовый prompt должен снимать «ожидание подтверждения».
- Журнал после завершения и архивации читается: `list_events` по заархивированной probe-1 вернул события (проверено до и после `archive_session`; `get_session` тоже работает, статус `ARCHIVED`).

Бюджет «до ~$0.10» превышен в 2,4 раза: основной вклад дала probe-1 (22 хода). Ориентир для ансамбля: один успешный исполнитель на небольшой задаче ≈ $0.15, холостая сессия, где агент отказался, ≈ $0.02–0.04.
